# 一次性购买与用户记录

`/stats/` 的「订阅与收入」按选定的 UTC 日期统计 `Purchase`：

- 只计入 `stripeLivemode = true` 的订单。
- 有效订单数、购买人数、金额和发放张数仅使用 `completed`；`refunded` 单列数量。
- 按 SKU、币种分别汇总，人数在每个套餐内去重，不应跨套餐相加。
- 购买用户列表包含完成和退款订单，每页 25 人。
- 金额是当前仍有效的订单金额，不是按退款发生日计算的现金流，也不进入 MRR / ARR。

用户详情由管理员接口提供，展示全部历史，可以切换时间正序或倒序，并分别分页。旧积分用量、每日免费额度和卡包张数采用不同口径，页面分别标识。

## 上线迁移

上线用户积分详情前，必须通过项目的数据库迁移流程执行：

`prisma/migrations/20260910000000_add_pack_credit_ledger/migration.sql`

仅执行 `prisma db push` 不会安装触发器。迁移会短暂锁定 User 表的写入，在同一事务中保存所有用户的期初卡包余额并安装触发器；读取不受该锁阻挡。

触发器在 User.packCredits 实际变化时写入 CreditLedger，覆盖 Stripe 充值、生成扣减、失败返还和手动余额调整。流水与余额更新同事务提交或回滚。零变动和失败的余额守卫不会生成流水。流水序号用于同一用户的稳定排序。

历史数据库没有逐笔消费记录，因此迁移前只展示期初快照、已有订单和每日用量，不反推历史余额，也不推断流水对应的具体生成任务。
